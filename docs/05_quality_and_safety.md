# 质量与安全规范

## 开发节奏

- 不一次性大规模改动前后端。
- 单次任务应能用一句话描述交付物。
- 涉及接口、数据库、认证、SSE 时，优先写清边界再实现。

## 验证标准

- 后端改动后至少运行一次 Python 语法检查或启动检查。
- 前端改动后至少运行一次 TypeScript 构建或静态检查。
- API 改动后更新文档中的接口说明。
- UI 改动后检查桌面宽度和窄屏宽度的文字不重叠。

## 安全要求

- 不把真实 API Key 写入代码。
- 密码必须哈希存储。
- 认证接口返回 JWT，不返回密码哈希。
- 前端本地保存 token 时，只用于演示原型；后续生产化需再评估安全策略。

## 日志要求

- 每天一个开发日志文件，路径格式：`dev-logs/YYYY-MM-DD.md`。
- 每次开发前写“计划事项”。
- 每次完成后写“完成事项”“验证结果”“待办事项”。
- 若遇到阻塞，必须写清楚阻塞原因和下一步处理方式。

## 变更安全

- 不删除既有检索脚本。
- 不重写用户已有代码，除非需求明确要求。
- 新增功能优先放入 `wenyuan-api/` 与 `wenyuan-web/`。
- 如果发现未预期的已有改动，应先记录，再决定是否继续。
